# Side Panel — нативный хост панели

Каталог зарезервирован под второй хост панели — нативный `chrome.sidePanel`.
Кода пока нет: документ фиксирует объём реализации, принятый по итогам
сравнения с решениями рынка (Sider, Page Assist, nano-prompt-ui).

## Назначение

Панель ИИ-ассистента рядом с **любой вкладкой браузера**. Разделение окна
выполняет сам браузер: страница вкладки не оборачивается, не сдвигается и
не мутируется. Компонент `@ui/sidebar` этот сценарий не покрывает и не должен —
он остаётся app-shell для собственных страниц приложения (два хоста, как у Sider:
in-page shell для своего DOM + нативная панель для чужих вкладок).

## Объём реализации

### 1. Манифест (`src/manifest.json`)

- Ключ `"side_panel": { "default_path": "src/side-panel/index.html" }`.
- Permission `"sidePanel"`.
- Для чтения контента активной вкладки — `"scripting"` и `"activeTab"`.

### 2. Точка входа

- `index.html` + `main.tsx` в этом каталоге — отдельная страница расширения,
  собирается `vite-plugin-web-extension` автоматически по ссылке из манифеста.
- Провайдеры те же, что в `src/main.tsx`: тема, тосты, глобальные стили
  (`GlobalResetStyle`, `GlobalThemeStyle`).

### 3. Каркас страницы

- Корень — вьюпорт панели целиком: `block-size: 100dvb`, `overflow: hidden`,
  grid «шапка + контент» (`grid-template-rows: auto minmax(0, 1fr)`).
- Скроллится только контентная зона — через `@ui/scroll-port`
  (кросс-системный скроллбар и вуали уже наследуют фон через `inherit`).
- Наполнение — существующие компоненты: `Card`, `Text`, `Button`, поля ввода.
  Ширину задаёт браузер (пользователь может менять её ручкой панели):
  фиксированных inline-размеров не закладывать, вёрстка тянется на `100%`.

### 4. Background (`src/background.ts`)

- `chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true })` —
  открытие по клику на иконку расширения (паттерн nano-prompt-ui).

### 5. Чтение контента вкладки

- Из UI панели по запросу: `chrome.scripting.executeScript` в активную вкладку
  (паттерн Page Assist). Постоянный content script не требуется.

## Вне объёма

- Инъекция панели в DOM чужих страниц (shadow DOM, iframe, мутация margin
  у `<html>` — путь Sider overlay/expand) — не реализуется.
- Рендер перехваченной страницы внутри собственного контейнера — отклонено:
  нереализуемо надёжно (CSP, X-Frame-Options, сессии), лидеры рынка так не делают.
- Изменения `@ui/sidebar` — не требуются, компоненты не пересекаются.

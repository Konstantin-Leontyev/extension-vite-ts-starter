# Общий UI-чеклист канона

Единый источник проверок UI для `project-coder` (самопроверка при письме), `project-reviewer` (отчёт ЗАМЕЧАНИЯ) и шага проверки на дубли у `project-orchestrator` (раздел «Дубли и лишние сущности»). Не дублировать дословно `project.mdc` — якоря § ведут в канон; при срабатывании читать раздел целиком.

Якоря «§N.M» без пометки — разделы `project.mdc`. Витрина — `showcase.mdc`. Иконки — `icons.mdc`.

### Архитектура стилей (§8.2–§8.4)

1. Классы пропсов и место дефолта — §8.2: вид дефолтится в генераторе, проброс — в `index.tsx`; дубль дефолта вниз по дереву запрещён.
2. Координация родитель → ребёнок — §8.3: статика — проп в JSX; динамический highlight — наследование CSS или канал переменной.
3. Лестница владения — §8.4: пропсы роли → layout-пропсы слота → канал состояний → геттеры для натива. Адресация ребёнка селектором для вида/состояний — нарушение; обёртка без функции — нарушение.

## Дубли и лишние сущности

Проверяется по фактическому выводу хелперов и по соседним компонентам, не по памяти: открыть тело вызванного хелпера и сравнить с тем, что дописано рядом.

- Декларация повторяет то, что уже отдал вызванный рядом хелпер (сетка, размеры, радиус, отступ, типографика) — §10.
- Селектор перекрывает собственный вывод хелпера, вызванного в том же генераторе: перекрытие допустимо только с обоснованием, иначе одно из двух лишнее — §10.
- Декларация не может примениться механикой CSS: проигрывает по специфичности глобальному правилу `reset.ts` (класс styled против `тег:псевдокласс`), мёртвая ветка условия, недостижимый селектор — §10.
- Тот же блок деклараций или та же логика (`resolve*`, обработчик, эффект, хук) собраны в двух и более местах — кандидат на общий хелпер или сателлит. Вынос предлагается в отчёте с указанием места; молча не выносить — §2.4.
- Сущность собрана локально там, где уже есть общий примитив, слот или хелпер (кнопка сброса, секция иконки, канал состояний, привязанная панель, позиционирование) — сверить с общим и назвать расхождение.
- Узел-обёртка без функции: несёт только проброс детей или один стиль, который принадлежит родителю или ребёнку — §8.4.
- Публичный проп вида дублирует уже существующий под другим именем (свой перечень вместо `*_KEYS`, свой дефолт поверх дефолта хелпера) — §4.2, §8.2.
- Атрибут состояния (`data-*`) выставлен в JSX, но его никто не читает — ни правило стилей, ни селектор в коде; либо читается на одном узле и мёртв на другом; либо булев проп печатает в разметку `"false"`, тогда как читается только `'true'` — §10.

## Distill (аудит starter; дополняет канон)

- **flex-комментарий** — каждый `display: flex` в `*.styles.ts` несёт обоснование «почему не grid» (исключения — уже в `project.mdc`). Голый flex без обоснования = нарушение (добавить комментарий; раскладку не менять).
- **anchored-panel dedup** — новый anchored-слой (показ в верхнем слое + dismiss + focus-trap + размещение) только через `@ui/anchored-panel`, не локальная копия связки хуков; режим и показ popover — только `@ui/popover`. ARIA (`role`, `aria-modal`, `aria-haspopup`) остаётся на виджете. Размещение — CSS-привязка к якорю по §13.4: панель открывающегося контрола берёт `getCssAnchorPlacementStyles`, панель со своей геометрией — `getCssAnchorBindingStyles` и пишет стороны сама. Расчёта координат в JS нет.
- **deep-import `../` между ui-примитивами** — в `src/ui/**` чужой примитив только через barrel `@ui/<name>`. Исключение: свой подпримитив (`./…`) и доменный модуль того же пакета. Grep `from '\.\./'` в `src/ui/**`.
- **table spacer** — невидимый spacer (`aria-hidden`, фикс. размер под отсутствующий сосед) допустим только с комментарием-инвариантом «зачем и что сломается при удалении». Иначе — замечание / правка.
- **semantic / landmarks** — один `<main>` на view задаёт **страница** (`pages/*`), не router и не корень `@ui/sidebar`. Card/блок с самостоятельным заголовком — `as="article"` / `as="section"` на call site (дефолт `div` — техн./popover-shell). Центральная модалка — `<dialog>` (`@ui/modal`), не portal-div.
- **Витрина / DS-canon** — самостоятельно применяемый `@ui/<name>` имеет секцию в `pages/showcase` (settings + widget); сателлит композиции секции не получает — `showcase.mdc`, «Какие компоненты получают секцию». Исключение, не сателлиты: ScrollPort и Sidebar секции не получают и отдельные карточки с крутилками у них не заводятся. Пример ScrollPort — Table, пример Sidebar — боковая панель страницы витрины. Demo-only упрощение помечено «Не переносить в продуктовый код»; при смеси с copyable — маркер указывает копируемую часть. Runtime-поток примитива показан, если он есть (напр. Toast через provider + hook). Имя настройки витрины не совпадает с пропом компонента при разном действии. Нет модуля-сироты в витрине.
- **Table nested head** — любая голова группы и строка товара — `TableGroupCell`, без отступа 24/48. У вложенной головы значок `↳`, затем стрелка. У товара значок стоит в колонке стрелки родителя: первым, если стрелка родителя первая, либо после резервного значка `TableMemberPrefix reserve`, если стрелка родителя сама стоит после `↳`.
- **Infra (при касании конфигов)** — stylelint покрывает `*.styles.ts`; eslint: barrel/`no-restricted-imports`, `import-x/no-duplicates`, `jsx-a11y`. Порядок CSS-свойств — зона stylelint, не ручной чеклист.

## Витрина (`pages/showcase`, showcase.mdc)

- Порядок полей настроек: `size → shape → tone → value` (пропуск отсутствующих пропов).
- Ключ `*WidgetState` совпадает с именем пропа примитива.
- Лейбл контрола — человеческая метка (`Size:`), не сырое имя пропа (`sizePreset`).
- Превью и runtime-путь передают один набор пропов.

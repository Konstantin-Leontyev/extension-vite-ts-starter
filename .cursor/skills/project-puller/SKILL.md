# Project-puller (зачаток)

Ты тянешь **уже готовый** нейтральный UI из канонического хаба в продукт. Хаб — репозиторий `extension-vite-ts-starter`. Правило хаба: `.cursor/rules/kit-hub.mdc` в хабе.

**Сам улучшения примитивов не придумываешь.** Нет нужного поведения в хабе — стоп, отчёт владельцу, правки делают в чате стартера.

Субагент: `.cursor/agents/project-puller.md`.  
**Модель:** `cursor-grok-4.6-xhigh`.

Это зачаток роли. Пока один конкретный случай: seolizer. Общий алгоритм ниже — чтобы следующий продукт не писать с нуля.

---

## ЧТО ТЯНУТЬ И ЧЕГО НЕ ТРОГАТЬ

- Тянуть: файлы примитива из хаба **целиком** (замена содержимого), плюс вызовы в продукте.
- Не тянуть: витрину (`pages/showcase`), продуктовые таблицы, кросс внешних сервисов.
- Спорный файл (нейтральный скелет + продуктовая начинка) — не затирать продукт целиком; вынести владельцу.

---

## СЛУЧАЙ 1 — seolizer, выбор языка

Источник правды после сдачи слияния в хабе: `Listbox` и `LocalePicker` стартера.

В seolizer уже работает свой переключатель:

- список продукта: `frontend/src/lib/locales.ts` — коды, подписи, `country` для флага, **`db` для Semrush**;
- UI: `frontend/src/components/locale-switcher/` — Combobox + `LocaleFlag` + `country-flag-icons`.

**Оставить в seolizer:** `LOCALES`, `LOCALE_CODES`, поле `db`, хук локали, всё что режет перечень под рынки Semrush. Стартер полный iso-639-1 сюда не подменяет продуктовый список.

**Сменить только импорт и оболочку:** LocaleSwitcher больше не импортирует Combobox. Берёт `Listbox` или `LocalePicker` из стянутого нейтрального UI. Опции по-прежнему из `LOCALES` (короткий список продукта), флаг в строке — как сейчас `icon: <LocaleFlag country={…}>`. Кросс локалей (`db`) у seolizer остаётся у себя.

Не делать в этом случае:

- не копировать `LOCALES` / `db` в стартер;
- не подменять продуктовый перечень полным списком либы;
- не тащить витрину стартера;
- не открывать Caption-downloader.

---

## ПОРЯДОК

1. Прочитай `kit-hub.mdc` в хабе.
2. Полный диф заявленных файлов хаб ↔ продукт. Cherry-pick «на глаз» запрещён.
3. Замени нейтральные файлы целиком. Поправь только call sites продукта (импорты, имена).
4. Прогон сборки и линта продукта. Сдача с ошибками запрещена.
